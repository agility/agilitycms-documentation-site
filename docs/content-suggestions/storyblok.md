# Content suggestions from Storyblok docs teardown

> Produced 2026-07-15 as part of the [rebuild plan](../rebuild-plan-2026.md) §9 competitor teardown. Compares Storyblok's docs surface (Guides / Concepts / Manuals / API references) against Agility's docs inventory from agilitycms.com/docs/sitemap.xml. Scope: content and articles only — UX/design/platform findings live in the teardown report.

**Baseline context.** Agility's inventory: Overview (18), Editors (~50), Developers (60), Owners & Admins (26), Training Guide (45), Apps (25), plus framework sections (Next.js 25, Gatsby 8, Nuxt 6, Eleventy 6, .NET 10, Astro 5, Angular 6, JavaScript SDK 11). Storyblok's surface: 8 technology guides each with a standardized sub-guide set, 20 developer Concepts pages, 18 User Manual sections, and multi-language API references. Two places Agility is already **ahead**: the role-based Training Guide (developer/architect/admin/editor tracks — Storyblok has no equivalent) and first-class MCP docs inside the docs IA (`/docs/developers/agility-cms-mcp-server`, `/docs/overview/agility-knowledgebase-mcp-server` — Storyblok's MCP docs are exiled to a labs subdomain and blog posts). *[Editor's note: the MCP article's IA placement is ahead, but its body is currently invisible to crawlers/AI due to the client-side markdown rendering bug — see the note in [sanity.md](sanity.md) §1.1.]*

## 2. Covered but weaker

| # | Topic | Agility today | Storyblok's treatment | What makes theirs stronger |
|---|---|---|---|---|
| 9 | **Framework getting-started tutorials** | `/docs/nextjs/next-js-and-agility-cms` + starter-first articles ("Using the Next.js Blog Starter") | https://www.storyblok.com/docs/guides/nextjs | Storyblok teaches a from-scratch integration in one linear page: `create-next-app` → install SDK → token → provider → render, with 7+ complete file-scoped copy-paste snippets. Agility's path leans on cloning a starter, which hides the mechanics and doesn't transfer to existing apps. Add a "from scratch in 15 minutes" tutorial per framework alongside the starters. |
| 10 | **Content Delivery API reference** | `/docs/developers/content-fetch-api` (single article) + `/docs/developers/testing-on-swagger` | https://www.storyblok.com/docs/api/content-delivery/v2 | Storyblok's reference is a structured tree (Introduction / Auth / Errors / Caching / Rate limits / Pagination, then per-resource pages) with code tabs in ~9–13 languages. Agility's is one prose article that outsources the contract to Swagger. Restructure Content Fetch API into per-endpoint reference pages with request/response examples in JS, C#, and cURL. |
| 11 | **Preview / visual editing developer concept** | `/docs/developers/setting-up-preview`, `/docs/editors/previewing-in-web-studio` | https://www.storyblok.com/docs/concepts/visual-editor | Storyblok's developer concept covers the full surface in one place: bridge setup, preview URL/slug configuration, SSL and CSP security requirements. Agility splits preview across editor and developer articles and doesn't document security constraints (CSP/iframe headers) for Web Studio embedding — a common integration blocker. |
| 12 | **Content modeling guidance** | `/docs/overview/content-architecture`, `/docs/developers/content-models` | https://www.storyblok.com/docs/concepts/content-modeling + per-framework `/docs/guides/nextjs/content-modeling` | Storyblok pairs an abstract patterns page with framework-specific "model → component" mapping guides showing real code. Agility's coverage explains the CMS features but not the design patterns (when to use a component vs. linked content vs. nested content, mapped to actual rendering code). |

## 3. Format gaps

| # | Format | Storyblok example | Suggestion for Agility |
|---|---|---|---|
| 13 | **Standardized sub-guide matrix per framework** — every technology gets the same sub-guides (Integration, Visual Preview, Dynamic Routing, Content Modeling, i18n) at predictable URLs | https://www.storyblok.com/docs/guides/nextjs/dynamic-routing et al. | Agility's framework sections are ad-hoc (Next.js has 25 mixed articles; Astro has 5). Define a fixed template — Quickstart / Web Studio Preview / Routing & Sitemaps / Content Modeling / Multi-locale / Deploying — and backfill every framework section to it. Gaps become visible and content stays parallel. |
| 14 | **A dedicated "Concepts" layer** separating platform-agnostic reference (tokens, caching, webhooks, references/linked content, roles) from how-to guides | https://www.storyblok.com/docs/concepts (20 pages) | Agility scatters conceptual material across Overview, Developers, and Training. A Concepts category (or a curated Concepts index page under Overview) would give both humans and AI retrieval a canonical page per concept instead of 3 partial ones. |
| 15 | **Multi-language code tabs in API docs** — one endpoint, tabs for cURL/JS/C#/Python | https://www.storyblok.com/docs/api/content-delivery/v2 | Agility's API articles show a single language (or none, deferring to Swagger). Given Agility's .NET heritage plus JS SDKs, tabbed JS + C# + cURL examples on every API page would serve both audiences from one URL. |

**Explicit non-gaps** (checked, no action needed): webhooks, workflows, roles/permissions, A/B testing (`/docs/owners-admins/a-b-n-testing-in-agility-cms`), e-commerce (starter + commercetools/BigCommerce apps), SSO/SAML, rich text customization, backups/DR, and starter templates all have Agility coverage at comparable or better depth. The Training Guide's linear role-based tracks are a differentiator Storyblok lacks — worth protecting and cross-linking from the framework quickstarts rather than restructuring.
